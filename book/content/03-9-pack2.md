### Q3.43 Coding: simulate a sliding-window sender. Given a stream of ACKs and timeouts, output which segments are retransmitted.
[GOOGLE · QUALCOMM · TECH-2 · ■■■ · T]{.meta}

[30-second answer: keep `base` (oldest unacknowledged) and `next` (next to send). A cumulative ACK for k advances `base` to k and releases new segments up to `base + N`; a repeated ACK of `base` three times, or a timer expiry, retransmits segment `base`.]{.short}

```c
#include <stdio.h>
/* ev[i] >= 0: cumulative ACK k (segments < k received); ev[i] == -1: timer expiry */
void run(int total, int N, const int *ev, int n) {
    int base = 0, next = 0, dup = 0;
    while (next < base + N && next < total) printf("send %d\n", next++);
    for (int i = 0; i < n; i++) {
        if (ev[i] == -1) {                       /* RTO: resend the oldest segment */
            if (base < next) printf("retransmit %d (timeout)\n", base);
        } else if (ev[i] > base) {               /* new data acknowledged */
            base = ev[i]; dup = 0;
            while (next < base + N && next < total) printf("send %d\n", next++);
        } else if (ev[i] == base && base < next && ++dup == 3) {
            printf("retransmit %d (fast)\n", base);
        }
    }
}
```

**Complexity.** O(total + events). **Follow-ups.** Go-Back-N would resend `base .. next − 1` on timeout; Selective Repeat needs a per-segment ACK flag; the timer restarts whenever `base` advances. **Mistakes.** Counting duplicates across new ACKs (reset `dup` when `base` moves), and sending beyond `base + N`.
:::
